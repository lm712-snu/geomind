The platform

From pixels to evidence you can inspect.

GeoMind is being designed around four connected capabilities. Each one makes the path from image to conclusion easier to inspect and reproduce.

01 / EXPLORE

Earth Explorer

Inspect imagery, coordinate reference systems, acquisition metadata, spatial extent, bands, and valid-data coverage before analysis.

02 / MEASURE

GeoAnalyzer

Run deterministic raster and spatial calculations, report units and valid coverage, and make assumptions visible instead of hiding them in prose.

03 / INTERPRET

GeoChat

A planned natural-language interface for asking questions about imagery, with quantitative claims tied to tools and evidence rather than model confidence alone.

04 / VERIFY

GeoProof

A structured evidence ledger for source, extent, operations, measurements, units, coverage, provenance, verification status, and limitations.

05 / COMPARE

Change with context

Compare observations only when dates, alignment, resolution, and valid coverage support a meaningful comparison. Differences are signals to investigate, not automatic proof of change.

06 / REPRODUCE

Research-ready outputs

Build toward repeatable analysis records, machine-readable outputs, documented methods, and evaluation protocols that can be independently checked.

The GeoProof principle

AI can interpret.
Measurements must be earned.

A fluent answer is not necessarily a factual one. GeoMind separates model-generated interpretation from measurements computed by explicit geospatial tools.

class proportion = class area ÷ valid area × 100%Illustrative formula. Actual results depend on the input raster, class definition, coordinate system, pixel area, and nodata mask.
GeoProof checks recorded calculations and provenance fields. It does not independently establish that source data are authentic or that a land-cover classification is correct.

Research roadmap

Build the evidence pipeline before the AI layer.

The research question is whether explicit GIS grounding improves factual accuracy and spatial consistency compared with image-only model responses.

Phase 01 · Current

Reliable foundations

GeoTIFF validation, area calculations, GeoProof schema, synthetic tests.

Phase 02

Real data workflow

Review data licences, add a small documented Earth-observation sample, establish a baseline.

Phase 03

Controlled evaluation

Compare image-only and evidence-grounded answers using defined metrics and held-out regions.

Phase 04

Reproducible demo

Integrate models only where compute allows; publish methods, limitations, and results.

This is a planned research programme, not a report of completed experiments. Dataset selection, model choice, and novelty claims remain subject to verification.
One integrated research workspace

Data. Evaluation. Reproducibility.

Bring the three next phases into one place. The tools below are usable in the browser for dataset planning, transparent paired-answer scoring, and exportable experiment records. They do not pretend a model has run when it has not.

PHASE 02 · DATA WORKFLOW

Start with documented Earth-observation data

Choose a public source, review its licence and access conditions, then record the exact asset you use. These links point to official dataset/project pages; no imagery is silently bundled into this website.

  • NASA Harmonized Landsat–Sentinel-2 (HLS) — harmonized optical observations; check product-specific terms and access requirements.
  • Copernicus Data Space Ecosystem — Sentinel data discovery and access; verify the specific product and terms.
  • BigEarthNet — labelled Sentinel-1/Sentinel-2 benchmark; review the dataset licence and intended use.
  • GEOBench-VLM — geospatial vision-language benchmark resources; check its repository and underlying dataset licences.
Your manifest will appear here. This records metadata you enter; it does not download or validate the remote scene.
Licence reminder: the dataset name alone is not a licence decision. Verify terms for the exact data product, labels, and any derived assets before redistribution or commercial use.
PHASE 03 · CONTROLLED EVALUATION

Compare two answers on the same question

Enter a reference answer and the two system responses for one evaluation item. Score using an explicit, simple rubric. These scores are human-entered labels—not automatic model evaluation.

Add an item and score both responses to create a paired record.
For a defensible experiment, predefine the rubric, evaluate enough independent items, blind reviewers where possible, split by geography—not random neighbouring tiles—and report uncertainty. One item is a workflow test, not a scientific result.
PHASE 04 · REPRODUCIBLE DEMO

Package the experiment so another person can inspect it

Export a run record that joins dataset provenance, evaluation scores, software/version notes, and limitations. You can save the metadata entered above as a local JSON file.

Research protocol ↗
Bundle will include the metadata and paired item recorded in this browser session. It will not include the source imagery or claim a model was run unless you document that run.
All processing in this workspace is local to your browser session. It does not call a vision-language model, upload your inputs, or run statistical significance tests. Model inference, real raster processing, and a sufficiently powered held-out evaluation remain separate research implementation tasks.
